\begin{abstract}
High-resolution drone imagery gives disaster-response teams street- and parcel-scale visual evidence, but it also creates a practical HPC bottleneck. Each cropped RGB image in our workflow has size $5440 \times 3648$, so repeated compression, reconstruction, storage movement, and visual inspection become expensive before downstream analysis begins. This summary studies conditional diffusion compression (CDC) as an operating-point problem for GPU systems. We ask which runtime controls make an existing CDC workflow usable for large disaster-imagery collections.
\end{abstract}

\section{Summary}

The workflow compresses full-resolution drone images with a pretrained x-parameterized CDC model and reconstructs them with a diffusion decoder on NCSA DeltaAI. Each experiment records wall time, peak GPU memory, bits per pixel (BPP), compression ratio, PSNR, SSIM, high-percentile error, and tiling seam metrics. We report compression ratio against uncompressed 8-bit RGB storage:
\begin{equation}
R=\frac{24}{\mathrm{BPP}}.
\end{equation}
For a candidate setting $\theta$, we track runtime and memory gains relative to a no-tiling baseline:
\begin{equation}
S_T(\theta)=1-\frac{T_\theta}{T_{\mathrm{base}}},
\qquad
G_M(\theta)=\frac{M_{\mathrm{base}}}{M_\theta}.
\end{equation}
These equations make the systems trade-off explicit; they do not replace image-quality review.

The native full-image baseline is feasible but costly. With 65 denoising steps, fp32 reporting, and batch size 1, the DeltaAI GH200 run takes about 144 seconds per image and peaks near 52 GB of GPU memory. Step reduction speeds decoding but does not remove the memory footprint. Resolution reduction is faster, but it discards spatial detail before compression. In the 20-image sweep, the 2K setting lowers runtime to about 7.36 seconds per image, yet SSIM drops to about 0.689, which is too aggressive for detailed visual inspection without downstream validation.

Tiling gives the strongest current operating point because it keeps the native image boundary while reducing the tensor size seen by the decoder. On 50 full-resolution images, $256 \times 256$ tiling lowers runtime from 144.35 to 79.84 seconds per image and peak memory from 52.01 to 1.66 GB. This is a 44.7\% runtime reduction and a 31.3$\times$ peak-memory reduction. It is also faster and smaller than $512 \times 512$ tiling, with only small PSNR and SSIM losses.

The main lesson is that CDC deployment for disaster imagery must be reported as a joint systems and image-quality problem. BPP and compression ratio are not enough. A useful setting must fit GPU memory, reconstruct quickly, preserve inspection details, and expose artifacts through comparisons and heatmaps. The current evidence supports $256 \times 256$ tiling as the best speed-memory candidate for the poster draft, with final-version updates planned for a larger sample, more visual panels, and downstream checks.
