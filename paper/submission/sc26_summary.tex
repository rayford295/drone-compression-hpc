\begin{abstract}
High-resolution drone imagery supports urban monitoring and disaster assessment, but large-area collections can reach hundreds of gigabytes. This summary aligns the SC26 poster with a PPO-based bitrate-allocation conditional diffusion compression (PCDC) framing. The public experiments evaluate the CDC/HPC operating point needed before trained block-wise PPO allocation results are reported.
\end{abstract}

\section{Summary}

The workflow compresses urban drone images cropped to $5440 \times 3648$ pixels with a pretrained x-parameterized CDC model and reconstructs them on NCSA DeltaAI. The broader PCDC design pairs this decoder with PPO-based block-wise bitrate allocation. The committed results do not yet evaluate that policy allocator; they measure the runtime, memory, bitrate, and visual-quality signals it will need. Each experiment records wall time, peak GPU memory, bits per pixel (BPP), compression ratio, PSNR, SSIM, high-percentile error, and tiling seam metrics. We report compression ratio against uncompressed 8-bit RGB storage:
\begin{equation}
R=\frac{24}{\mathrm{BPP}}.
\end{equation}
For a candidate setting $\theta$, we track runtime and memory gains relative to a no-tiling baseline:
\begin{equation}
S_T(\theta)=1-\frac{T_\theta}{T_{\mathrm{base}}},
\qquad
G_M(\theta)=\frac{M_{\mathrm{base}}}{M_\theta}.
\end{equation}
These equations make the systems trade-off explicit; they do not replace image-quality review.

The native full-image baseline is feasible but costly. With 65 denoising steps, fp32 reporting, and batch size 1, the DeltaAI GH200 run takes about 144 seconds per image and peaks near 52 GB of GPU memory. Step reduction speeds decoding but does not remove the memory footprint. Resolution reduction is faster, but it discards spatial detail before compression. In the 20-image sweep, 2K lowers runtime to about 7.36 seconds per image, yet SSIM drops to about 0.689.

Tiling gives the strongest current operating point because it keeps the native image boundary while reducing the tensor size seen by the decoder. On 50 full-resolution images, $256 \times 256$ tiling lowers runtime from 144.35 to 79.84 seconds per image and peak memory from 52.01 to 1.66 GB. This is a 44.7\% runtime reduction and a 31.3$\times$ peak-memory reduction. It is also faster and smaller than $512 \times 512$ tiling, with only small PSNR and SSIM losses.

CDC and future PCDC deployment for disaster imagery must be reported as a joint systems and image-quality problem. BPP and compression ratio are not enough. A useful setting must fit GPU memory, reconstruct quickly, preserve inspection details, and expose artifacts through comparisons and heatmaps. The current evidence supports $256 \times 256$ tiling as the best speed-memory candidate for the poster draft. Final updates should add a larger sample, more visual panels, downstream checks, and the PPO-based block-wise allocator.
